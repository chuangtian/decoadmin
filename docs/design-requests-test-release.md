# 设计需求管理测试服发布

## 目标

在工作台下增加“设计需求”板块，提供效率总览和需求列表，并按登录用户执行服务端数据隔离。

## 权限

- 普通提报人拥有 `design_requests.view` 和 `design_requests.create`，只能查看本人提交的需求及本人范围的效率数据。
- 新增系统角色“设计师”，拥有 `design_requests.view_all` 和 `design_requests.manage`，可以查看当前店铺全部人员需求、分配设计师并更新交付状态。
- 组织管理员、店铺管理员和超级管理员拥有全部设计需求权限。
- 所有查询、统计和更新均校验当前组织与店铺。前端筛选参数不能扩大服务端数据范围，跨店铺记录返回 404。

## 页面与流程

- 效率总览展示需求总数、处理中、已完成、已延期、状态分布、按时交付率、平均交付周期、累计改稿及待分配数量。
- 需求列表支持编号或描述搜索，并可按需求类型、优先级和状态筛选。
- 提报表单包含需求类型、优先级、部门、数量、计划交付日期及需求描述。提报人、提报日期和初始状态由服务端生成，客户端不能冒用其他用户或指定设计师。
- 设计师与管理员可以分配设计师、修改状态和交付日期、记录改稿次数及交付说明。进入处理流程前必须分配设计师，标记完成时必须填写实际交付日期。
- 状态包括待分配、已分配、设计中、待确认、已完成和已取消；延期天数由计划与实际交付日期自动计算。
- 创建及更新写入审计日志，日志不保存附件或敏感凭证。

## 数据结构

- 新增 `design_requests` 表，按组织、店铺、提报人、设计师和状态建立索引。
- 使用不可枚举 UUID 作为页面更新标识，需求编号用于界面识别。
- 新增四项独立权限和设计师系统角色；迁移为现有系统角色补齐合理的初始权限，种子脚本支持新环境。

## 验证

- 功能测试覆盖提报人互相不可见、设计师查看全部、管理员与设计师更新、跨店铺阻断、强制绑定当前登录提报人、初始状态和审计记录。
- 回归测试覆盖现有 RBAC 与数据库基础结构。
- Vue 类型检查、正式前端构建、PHP 格式检查通过。

本次仅发布测试服，不修改正式服。
